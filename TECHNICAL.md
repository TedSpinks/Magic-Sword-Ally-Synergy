# Technical notes

Details that don't belong in the README: building, how the patch is put together, memory use, testing and known limits. Research and the full development history are in [`docs/`](docs/).

## Patched ROM checksums
`MagicSword_AllySynergy.ips` applied to the clean ROM (Magic Sword (USA), 1 MB, no header, CRC32 `27325E4D`, SHA-1 `0d64ef4149b71d13d287122f58eca9c580fa7d0f`):

| Patch | IPS size | Patched ROM size | Patched ROM CRC32 |
|---|---|---|---|
| `MagicSword_AllySynergy.ips` | 64,090 B | 1 MB | `F15F25E8` |

## Building
`python3 build.py "/path/to/Magic Sword (USA).sfc" [outdir]` (output goes to `out/` by default, which is not committed):
1. checks the clean ROM's CRC32 and SHA-1;
2. applies kandowontu's FastROM patch (`inputs/third_party/fastrom.ips`);
3. assembles the files in `src/` with asar, in this order: `hack_opt`, `recruit`, `bigregen`, `priest`, `wizard`, `mfix2`, `ninja`, `text`, `options`, `save`, `slot` (includes `hiscore` and `logpage`), `hints`, `bosswarn`, `thieflog`, `items`;
4. writes the IPS as the difference from the clean ROM, checks that applying it reproduces the build byte for byte, and packs the release zip (IPS, `README.md`, `SECRETS.txt`, `CHECKSUMS.txt`).

Needs [asar](https://github.com/RPGHacker/asar) 1.9x (1.91 was used; in `tools/` or on `PATH`) and Python 3.

The `.bin` and `.inc` files in `src/` are generated data (icon tiles, map strip tiles and palettes, star fields, text lists) and are committed so the build needs nothing but asar. The scripts that made them are in `tools/` (see below); they were run from a working folder, so their paths need adjusting before re-running.

## Memory use
- **SRAM (2 KB, `$70:0000`):** options at `$0010`; saved runs at `$0100`, `$0200`, `$0300` (marker, name, checksum, the run state `$0403-$0491`); Hall of Heroes at `$0400`; Thief's Log at `$0500` (marker, 56 floor bits, check, pending warp).
- **WRAM the game never touches:** `$7E:2600-$6FFF` and `$7E:0300-$03FF` (checked on every floor). The pause view's backups use `$7E:2600-$5A57`; the live floor list copy uses `$7E:5FF0-$6FEF`; the attract-demo flag is `$7E:6FF0` and the last scene (which tells the title that a run just ended) `$7E:6FF8`.
- **`$7F:E000-$FFFF`**: a floor load writes over it (`$7F:E700-$E7FF` included); the game doesn't read or write `$7F:E700-$E7FF` during play after that (checked by filling it with junk every frame on several floors). The CODEX, Resume screen, Hall of Heroes and the pause view use `$7F:E000+` only while they run (the pause view backs it up first), and the Thief's door icons keep working values in `$7F:E7C0-$E7E6` that only matter within a floor. Anything that must survive play lives in SRAM or in the untouched area above.
- **Scratch bytes `$0771-$0787`** (perks, pop-ups, random numbers): checked unused by the game.

## Design choices
- **One patch, made from a clean ROM.** FastROM is included; applying it first, or patching an already patched ROM, is not supported.
- **The attract demo** replays recorded input: perks check the demo state where they could change it, and nothing is saved or recorded during it.
- **The Thief's Log** draws every map from the ROM's floor lists (the usual layout). A record's position is where the screen's edge triggers it, not where its object appears: cell doors, chests and the exit are placed where the game actually puts them (from the record's spawn offset and each floor's start scroll; on the right-to-left floors 10 and 20 they come in from the left), the start arrow points the way the floor runs, and icons that would overlap are nudged toward the floor's start (left on those two floors) so their order stays right. The game shuffles some cell doors and chests each time a floor loads (`docs/DOOR_CONTENTS.md`); the pause view draws the floor being played from the game's live copy instead, so that one map always matches. Floors 51-55 (the ending scenes) are never recorded.
- **The header checksum** is correct in the patched ROM.

## Testing
Run on Snes9x (libretro, with a few memory-inspection hooks: `tests/tw_core.patch`) through a Python driver (`tests/lr.py`). The main checks for 1.0.0 (re-run on the slot screen and resume flow for 1.0.1):
- **Pause view memory safety** (`tests/pv8.py`): on every floor 1-54, at several points while walking and fighting (and through every boss), pause -> Thief's Log -> back gives the same screen, VRAM, CGRAM, OAM, PPU/DMA registers and WRAM as a plain pause, outside the documented backup areas. START from the view vs a plain unpause, compared frame by frame.
- **Live floor list** (`tests/wl1.py`, `tests/lv2.py`): the game's live floor list keeps every record's position during play on every floor; the pause map matches the unshuffled map except where the doors were shuffled.
- **Text** (`tests/v65t.py`, `tests/cx117.py`, `tests/textdump.py`): every between-level message rendered and compared; CODEX ally and item pages captured.
- **Saves, options and resets** (`tests/rs115.py`): RESET CODEX choices, option save and reload, soft reset into the CODEX.
- **Endings** (`tests/end2.py`) and the Thief's Log floor marking (`tests/t118.py`).
- **Perks:** the assembled routines run through a small 65816 interpreter (`tools/sim65.py`) for every level and ally combination where a live test was impractical (Amazon carry-over, Cleric food bonus).
- **Playtesting:** every floor played start to finish in RetroArch (Snes9x core).

The test scripts need save states and the patched core, which are not in the repository (save states contain game data). See [`tests/README.md`](tests/README.md).

## Known limits
- Mostly tested on Snes9x. bsnes (accuracy core, with random power-on RAM) and Mesen-S were used for the resume and power-on checks described above; the rest of the suite has not been run on them. Not tested on real hardware.
- Loading an emulator save state replaces the game's battery save with the copy inside the state.
- Resuming a saved run reloads the floor, which reshuffles its shuffled doors (original game behavior).
